# Zotero与Obsidian联动规范

## 1. 联动原则

- Zotero负责：条目、集合、作者、DOI、附件、标签、引文导出。
- Obsidian负责：Markdown、论证链、原文定位、图表卡、研究空白、双向链接。
- Excel负责：批量筛选、横向比较、统计和交付。
- 同一信息只指定一个主来源；另一系统保存链接或只读镜像，避免双向覆盖造成冲突。

## 2.1 应用联动执行顺序

当用户提供`@Zotero`或`@Obsidian`应用提及时，优先使用已连接的应用状态，不要猜测库、集合或Vault路径。进行Windows界面操作前，先遵循`computer-use`技能的初始化、目标窗口、截图和确认规则；如果只有本地文件能力，则使用导出文件/本地Vault路径并在报告中标明“未执行应用内同步”。

应用内联动采用“先读后写、先清单后批量”的顺序：

1. 读取当前库/Vault和目标条目，不立即修改；
2. 生成变更预览：新增集合、待导入条目、待修改标签、待挂接附件、待写入笔记；
3. 当前阶段通过用户验收后，执行对应写操作；
4. 写入后重新读取抽样条目和文件，验证实际状态；
5. 将成功、失败、未执行和需人工复核分别写入批次报告。

如果应用不可用、窗口状态无法确认、目标条目无法唯一匹配或写入结果无法回读，暂停本阶段，不用本地生成的文件冒充“已同步”。
## 2. Zotero连接策略

### 可通过桌面应用/电脑使用能力操作时

1. 读取当前库、集合和条目总数；
2. 创建或复用顶层集合`AI文献库`；
3. 在顶层集合下创建分类集合；
4. 导入或更新条目，不删除用户已有条目；
5. 将PDF/SI作为附件挂接到正确条目；
6. 保留原标签，追加命名空间标签；
7. 写入或更新条目笔记中的Obsidian链接、批次ID和处理状态；
8. 对不可确认的修改先生成差异清单，验收通过后再批量修改。

### 无法直接连接时

接收用户导出的JSON/BibTeX/RIS/CSV或Zotero库快照；本地生成可导入文件和修改清单，并将“未同步Zotero”列入验收报告。不得声称已经改动Zotero。

## 3. Zotero集合和标签建议

```text
AI文献库/
├── 00-待分类
├── 01-后量子密码学
├── 02-零知识证明与递归证明
├── 03-隐私增强计算
├── 04-实现安全与侧信道
├── 05-区块链与分布式密码学
└── 99-待人工复核
```

标签命名空间：

```text
source:zotero
status:待筛选 | 在读 | 已精读 | 已复用 | 待核验
topic:PQC/格密码
 type:理论分析 | 实证研究 | 综述 | 案例研究 | 实验研究 | 方法改进
primitive:Kyber | FHE | MPC | ZKP
domain:联邦学习 | 区块链 | 侧信道
technique:NTT | 递归证明 | 差分隐私
dataset:名称或未提及
metric:延迟 | 吞吐量 | 通信开销
figure:已提取 | 未核验
evidence:直接证据 | 部分完整 | 未核验
```

标签值使用短语；详细判断放入论文笔记。若标签冲突，保留原标签并添加`review:tag-conflict`，不要直接删除原值。

## 4. Obsidian目录和链接

建立或复用以下目录：

```text
00-系统说明/
01-精华论文/
02-研究主题/
99-佐证资料/完整论文笔记/{分类}/
99-佐证资料/图表与证据卡/{分类}/{论文短标题}/
03-研究空白与可复用资产/概念与术语/
03-研究空白与可复用资产/研究空白/
03-研究空白与可复用资产/可复用科研资产/
99-佐证资料/参考文献/
09-模板/
99-佐证资料/原始论文/
99-待人工复核/
```

论文主笔记使用Obsidian wikilink：

```markdown
- Zotero：`zotero://select/library/items/ITEMKEY`
- 论文索引：[[01-精华论文/论文总览]]
- 图表卡：[[99-佐证资料/图表与证据卡/PQC/论文短标题/Figure-01-性能比较]]
- 关联论文：[[99-佐证资料/完整论文笔记/PQC/另一篇论文--2024--456]]
- 研究空白：[[03-研究空白与可复用资产/研究空白/跨平台验证不足]]
```

只有在Item Key已核验时才写Zotero URI；只有在目标文件已实际创建时才写Obsidian wikilink。无法验证的链接标记`link_status:待核验`。

## 5. 附件处理

- 原始PDF/SI：`99-佐证资料/原始论文/{分类}/{论文短标题}--{年份}--{ItemID}/`；原件不改名或另存副本。
- 图表派生素材：`99-佐证资料/图表与证据卡/`；每张只含一个图或表的裁剪图。
- 论文笔记不要嵌入整页截图；只嵌入图表裁剪图和必要的公式/表格。
- 图片相对路径必须以论文笔记所在位置为基准验证。
- 附件命名冲突时增加ItemID，不覆盖原文件。

## 6. 双向关系同步

关系类型固定为：支持、补充、拓展、对比、评估、应用、重复、冲突、替代、依赖。

一条关系最少包含：

```yaml
relation: "对比"
target: "[[论文B]]"
reason: "两文均比较吞吐量，但硬件和输入规模不同"
evidence: "[[Figure-论文A-02]]; [[Table-论文B-01]]"
comparability: "部分可比"
```

如果关系只由个人判断得出，标记为`interpretation_level:个人推论`，不得写成作者主张。

## 7. Dataview索引

若Vault启用了Dataview，论文索引可使用：

```dataview
TABLE category, year, paper_type, reading_status, evidence_status, fulltext_status
FROM "99-佐证资料/完整论文笔记"
WHERE record_type = "paper"
SORT year DESC
```

图表索引可使用：

```dataview
TABLE paper_item_id, figure_id, figure_type, source_page, verification_status
FROM "99-佐证资料/图表与证据卡"
WHERE record_type = "figure-evidence"
SORT paper_item_id, figure_id
```

若Dataview不可用，仍生成普通Markdown表格，不把Dataview视为必要依赖。

## 8. 同步验收

同步完成后至少检查：

- Zotero条目数和分类集合数量；
- 每个PDF/SI是否挂接到正确Item；
- 原有标签是否保留；
- Obsidian主笔记是否存在；
- 图表卡片和图片是否一一对应；
- wikilink、Zotero URI和相对图片路径是否可解析；
- Excel行数是否与论文集合一致；
- 所有未同步内容是否出现在`99-待人工复核`。
