# Paper Record执行工作流

## 1. 任务入口

收到`papaer-record`后，先判断用户意图：

- **新建库**：从Zotero空库或指定检索主题开始；
- **增量整理**：处理已有Zotero条目、附件或指定分类；
- **同步**：只把已存在的Zotero内容同步到Obsidian；
- **深读**：只处理指定分类或指定论文；
- **修复**：只修复某阶段的错配、标签、图表、引用或链接问题。

若用户同时提出多项任务，拆成阶段，不一次性无门槛执行完。先记录范围、输入、目标输出和当前阶段。

## 2. 处理批次

每次运行创建一个批次ID，例如：

同一批次重跑时应复用批次ID并记录事件；新范围或新版本使用新批次ID。

```text
PR-20260914-001
```

批次目录：

```text
PaperRecord_Output/
└── batches/
    └── PR-20260914-001/
        ├── manifest.json
        ├── input-snapshot/
        ├── reports/
        ├── staging/
        └── derived/
```

- `input-snapshot/`：仅保存导出副本或输入清单，不修改原件；
- `staging/`：解析中的中间文件；
- `derived/`：通过验收后复制到Obsidian/Vault和其他正式目录；
- `reports/`：阶段报告和验收报告。

## 3. 阶段执行顺序

### Stage 0：盘点与计划

采集：

- Zotero库名称、集合、条目数量、附件数量；
- 是否有`AI文献库`；
- Obsidian当前Vault及路径；
- 已有论文矩阵、Markdown、图表、PDF、SI和BibTeX；
- 用户指定主题、语言、时间范围、分类和输出路径。

输出：`00-系统说明/批次日志/{批次ID}-stage-0.md`和计划。此阶段不改动条目。

### Stage 1：检索与导入

执行顺序：

1. 明确检索式、年份范围、英文文献标准和排除标准；
2. 检索并记录每条候选文献的来源、命中理由和链接；
3. 以DOI优先、题名+第一作者+年份次之去重；
4. 在Zotero建立`AI文献库`；
5. 创建分类集合，必要时建立“待分类”；
6. 导入元数据和可获得的PDF；
7. 写入结构化标签；
8. 生成导入清单和分类解释。

不要将搜索结果的摘要直接写成深度结论。

### Stage 2：全文与SI

对每个条目记录：

```text
pdf_status: 已获取 / 未获取 / 仅链接 / 待核验
si_status: 已获取 / 未获取 / 不适用 / 待核验
source_url:
si_url:
attachment_item_id:
failure_reason:
```

下载后先核对PDF的题名、作者、DOI或正文首页，再挂接到对应Zotero条目。无法核对的文件不自动挂接。

### Stage 3：人工文件挂接

对用户指定目录中的每个文件建立匹配候选：

1. DOI完全匹配；
2. 标准化题名完全匹配；
3. 作者、年份和题名相似度匹配；
4. PDF正文中的DOI/题名再验证。

只对唯一高置信匹配执行挂接。多个候选、缺少元数据、同题名不同版本均进入人工复核。

### Stage 4：矩阵与引用

矩阵表每篇论文一行；分类Sheet或Markdown分类表每组单独呈现。APA引用从已核验元数据生成；缺字段保留“未提及/未核验”，不得猜测。

### Stage 5：标签治理

保留原标签；新增命名空间标签。一个标签只表达一个维度，不将整句结论做成标签。标签变更前输出差异清单，避免覆盖用户标签。

### Stage 6：引用溯源

逐篇解析参考文献，保持两张表：

- `reference_master`：去重后的标准化参考文献；
- `reference_occurrence`：每个来源论文中的出现记录。

去重绝不能删除“哪篇论文引用了它”的关系。

### Stage 7：深度阅读与图表

每篇论文按以下顺序提取：

```text
研究缺口 → 研究问题 → 方法 → 数据/实验 → 图表 → 结果 → 结论 → 局限
```

图表必须：

- 定位原文页码和章节；
- 裁剪为只含图表本体的图像；
- 在对应章节附近插入图片链接；
- 建立独立图表证据卡；
- 绑定正文主张、研究问题和结论；
- 明确实验边界和不可外推内容。

## 4. 深读的三种输出深度

### 快速卡

适用于首次筛选：三分钟速读、研究问题、方法、最重要结果、最大局限、阅读价值。

### 标准卡

适用于论文矩阵和日常复习：14字段、论证链、关键图表、原文定位、参考文献和关联论文。

### 深度卡

适用于写综述或设计实验：逐节阅读、图文联合解析、变量和参数、统计结果、复现条件、证据强度、结论边界、跨论文差异和研究空白。

用户未指定时，先生成标准卡；指定“深入阅读/细致整理/用于写作”时使用深度卡。

## 5. 输出后的同步顺序

1. 生成并验证中间结构化数据；
2. 生成论文矩阵和报告；
3. 生成主笔记、图表证据卡和分类小结；
4. 验证相对路径、wikilink和Dataview字段；
5. 将已通过当前阶段的结果同步到Obsidian；
6. 将书目/附件/标签变更同步到Zotero；
7. 写入批次清单和变更摘要；每个已处理文件立即登记业务分类。

若同步失败，保留可导入文件并在验收报告中标注，不伪称已同步。

## 6. 用户验收后续

- 用户说“验收通过”：锁定本阶段版本，推进一个下一阶段；
- 用户说“优化”：保留旧版本，定位问题并只重做指定部分；
- 用户说“停止”：保留当前批次和报告，不再修改；
- 用户没有明确验收：不自动跨阶段。
