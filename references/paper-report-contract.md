# 逐篇主报告合同（Paper Record 3.1）

每篇论文只允许有一份主叙事报告：`02-深度说理报告.md`。它不是摘要扩写，也不是章节标题集合，而是一份能够让不了解论文的读者从零跟上作者推理的证据型讲解稿。

## 强制论证链

```text
背景/对象
→ 具体瓶颈
→ 研究目的与核心问题
→ 理论/假设/威胁模型
→ 作者观察
→ 设计选择
→ 方法执行
→ 实验/证明/评测
→ 图表/公式证据
→ 结果
→ 作者结论
→ 结构化转述
→ 本次综合推论
→ 局限/外推边界
→ 复现与复用
```

## 强制结构

1. **一句话定位与阅读范围**：论文类型、直接相关性、核对的版本和材料范围。
2. **从零理解问题**：对象、场景、先修概念、已有路线和具体瓶颈。
3. **研究目的与核心问题**：分开回答为什么做和要回答什么。
4. **理论、假设与威胁模型**：每个核心概念必须写“是什么—本文如何使用—关键假设—不成立的后果”。
5. **作者观察与思路重建**：观察→矛盾/瓶颈→假设→中间表示→设计选择→预期机制。
6. **方法执行链**：输入、预处理、步骤、中间状态、输出、失败分支、复杂度或资源预算。
7. **实验/证明/评测逻辑**：验证哪条假设，数据/模型、基线、变量、指标、成功判据、异常和负结果。
8. **图表、公式与结果证据**：逐项链接证据卡，说明能推出什么、不能推出什么。
9. **结果到结论**：分别标注原文证据、结构化转述和综合推论。
10. **局限、未报告信息与外推边界**：区分作者明确局限、条件限制、材料缺失和整理者推论。
11. **复现与复用**：环境、参数、数据、代码、最小步骤、风险和可复用变量。
12. **读者最终应记住的 5 件事**：必须是论文特异性结论。

## 论文特异性最低要求

- 全文主要章节均有覆盖记录；
- 至少 8 个论文特异性事实；
- 至少 8 个有效全文锚点；
- 至少 3 个理论/假设概念的“使用方式—失效后果”解释；
- 至少 1 条完整的作者思路因果链；
- 方法至少包含输入、中间状态、输出和失败分支；
- 实验至少包含变量、基线、指标和成功判据；
- 每个核心图/表/公式都登记支持 Claim 和不能推出项；
- 作者主张、结构化转述和本次综合推论不能混写。

## 证据段落格式

核心段落必须包含以下信息中的全部适用项：

```text
[原文证据] PDF 页码/章节/图表/公式 + 可核验事实
[结构化转述] 不增加原文没有的因果关系
[本次综合推论] 说明推理跨度和所依赖的多个 Evidence
Evidence / Material ID
适用条件与边界
```

## 按论文类型适配

- 理论/证明：用定义、定理、证明义务、假设和反例检查替代实验字段；
- 实证/基准：强调样本、划分、污染、指标、统计不确定性和基线；
- 系统/工程：强调威胁模型、接口、资源预算、故障模式和部署条件；
- 攻击/密码分析：明确目标、轮数/范围、密钥信息、成功率和复杂度，禁止扩大攻击结论；
- 综述：明确检索策略、纳入标准、分类框架和证据覆盖，不能把综述观点写成新实验结论。

## 禁止的空洞表述

以下内容不能作为论文结论：

- “采用某算法，效果较好”；
- “具有理论、方法和实践意义”；
- “见论文”或“详见实验部分”；
- 只有工具名、只有数字、只有路径而没有用途；
- 把语法通过写成安全性证明；
- 把缩减轮结果写成全轮破解；
- 把密钥差值恢复写成完整密钥恢复；
- 把问答准确率写成协议安全性。
